# 자모 오피스 (Jamo Office)

**한글(.hwp/.hwpx)·워드(.docx)·파워포인트(.pptx)를 브라우저에서 열고 고치는 무료 편집기.**

파일은 기기를 떠나지 않습니다. 서버가 없고, 모든 처리가 브라우저 안에서 끝납니다.

```bash
npm install
npm run dev           # 개발 서버
npm run build:single  # HTML 파일 하나로 빌드 → apps/editor/dist/jamo-office.html
```

`build:single` 이 만드는 **`jamo-office.html` 파일 하나를 더블클릭하면 그대로 열립니다.**
웹서버도, 설치도, 인터넷도 필요 없습니다. 349KB짜리 파일 하나가 전부입니다.
USB에 담아 다른 컴퓨터에서 열어도 똑같이 동작합니다.

여러 파일로 나뉜 보통의 정적 빌드가 필요하면 `npm run build:web` 을 쓰세요
(263KB, gzip 87KB).

## 지금 되는 것

| 형식 | 열기 | 편집 | 저장 | 비고 |
|---|:---:|:---:|:---:|---|
| `.hwpx` 한글 | ✅ | ✅ | ✅ | 개방 표준(KS X 6101) |
| `.hwp` 한글(구형) | ✅ | — | — | 읽기 전용. `.hwpx`/`.docx`로 변환 후 편집 |
| `.docx` 워드 | ✅ | ✅ | ✅ | |
| `.pptx` 파워포인트 | ✅ | ✅ | ✅ | 슬라이드 추가·삭제·텍스트 편집 |

**형식 간 변환**은 모두 가능합니다. 한글 → 워드, 워드 → 한글, 문서 → 슬라이드까지.

### 편집할 수 있는 것

- 글자 입력·수정, **진하게·기울임·밑줄·취소선**, 글자 크기·색
- **문단 정렬**(왼쪽·가운데·오른쪽·양쪽), 들여쓰기
- **표** — 격자로 크기 고르기, 줄·칸 추가·삭제, **셀 합치기·나누기**, 칸 배경색,
  `Tab` 으로 칸 이동 (마지막 칸에서 `Tab` 이면 줄이 늘어남)
- **슬라이드를 보이는 대로 표시** — 배경, 테마 색, 그림, 도형 채우기, 마스터·
  레이아웃 장식, 글자 서식 상속까지. 슬라이드 추가·삭제, 글상자 글자 편집
- **되돌리기 / 다시 실행**

이미지·차트·도형 삽입은 아직 없습니다. 다만 **파일 안에 있던 것은 저장해도
사라지지 않습니다.** 표가 든 문서를 열어 글자 하나만 고쳐 저장해도 표·그림·각주가
그대로 남습니다. 이게 이 프로젝트의 가장 중요한 약속입니다.

무엇이 되고 무엇이 안 되는지 전부 적은 대조표: **[docs/FEATURES.md](docs/FEATURES.md)**

### 쓰는 법

1. 파일을 창에 끌어다 놓거나 `파일 열기`
2. 문단을 클릭해 고침 (Enter = 새 문단, 빈 문단에서 Backspace = 삭제)
3. `Ctrl+S` 로 저장

### 설치해서 쓰기

두 가지 길이 있습니다. 둘 다 서버가 없고, 파일은 기기를 떠나지 않습니다.

**① 앱으로 설치 (권장)** — 웹 주소로 열고 도구막대의 **앱 설치**를 누르면

- 바탕화면·작업표시줄에 아이콘이 생기고 **주소창 없는 전용 창**으로 뜹니다
- 한 번 열어 두면 **인터넷 없이도** 열립니다 (서비스 워커가 미리 받아 둡니다)
- 탐색기에서 **`.hwpx` `.hwp` `.docx` `.pptx` 를 더블클릭하면 이 앱이 엽니다.**
  그렇게 연 파일은 `Ctrl+S` 로 원래 자리에 그대로 덮어쓰입니다

사파리는 설치 신호를 주지 않아 버튼이 안 뜹니다. `공유 → 홈 화면에 추가`로
같은 결과가 됩니다.

**② 파일 하나로** — `npm run build:single` 이 만드는
`apps/editor/dist/jamo-office-<판번호>.html` 를 더블클릭하면 그대로 열립니다.
파일 이름과 화면 왼쪽 위에 **빌드한 시각**이 적혀 있습니다 — 받은 파일이
여러 개 쌓였을 때 어느 게 최신인지 알려면 그 숫자를 보세요.
설치도 인터넷도 필요 없고 USB 에 넣어 다녀도 됩니다. 대신 파일 연결과
자동 갱신은 없습니다.

### 발표와 강의용 메모

슬라이드를 열면 아래에 **메모판**이 붙습니다. 여기 적은 글은 청중 화면에
나오지 않고, 파워포인트의 "슬라이드 노트"에 그대로 들어갑니다.
메모판 위의 **경계선을 끌어** 크기를 조절합니다. 기본은 **폭 맞춤**이라
메모판을 끌어도 장표 폭은 그대로이고 세로로 보이는 만큼만 달라집니다 —
조금 끌 때마다 장표가 가로세로로 같이 출렁이지 않습니다. 장표 전체를 한눈에
보려면 도구막대 가운데 단추를 눌러 **화면 맞춤**으로 바꿉니다.

- `F5` 처음부터 발표 · `Shift+F5` 현재 장부터
- 발표 중 **`S`** — 발표자 보기 (그 장의 메모 · 다음 장 · 경과 시간)
- `B` 검은 화면 · `W` 흰 화면 · `Esc` 끝내기

### 단축키 — 워드 키와 한글 키를 둘 다 받습니다

가운데 정렬이 워드는 `Ctrl+E`, 한글은 `Ctrl+Shift+C` 인데 **둘 다 동작합니다.**
어느 쪽에서 오셨든 손에 익은 키가 그대로 먹습니다. 프로그램 안에서 `F1`.

| | 워드 키 | 한글 키 |
|---|---|---|
| 진하게 / 기울임 / 밑줄 | `Ctrl+B` `Ctrl+I` `Ctrl+U` | 같음 |
| 가운데 정렬 | `Ctrl+E` | `Ctrl+Shift+C` |
| 글자 크게 | `Ctrl+Shift+.` | `Ctrl+]` |
| 다시 실행 | `Ctrl+Y` | `Ctrl+Shift+Z` |
| 표 만들기 | — | `Ctrl+Alt+T` (원래 `Ctrl+N,T`) |

한글의 `Ctrl+N,T` 는 브라우저가 `Ctrl+N` 을 먼저 가져가서 쓸 수 없습니다.
데스크톱 앱으로 감싸면 이 제약이 사라집니다. 전체 목록과 사정은
**[docs/SHORTCUTS.md](docs/SHORTCUTS.md)**.

크롬·엣지에서는 **열었던 파일에 그대로 덮어씁니다.** 파이어폭스·사파리는 내려받기로
떨어집니다 (File System Access API 미지원).

## 왜 이렇게 만들었나

### 1. 역공학이 아니라 공개 표준 구현입니다

이 프로젝트가 다루는 형식은 모두 **문서가 공개된 표준**입니다.

- **HWPX** — 한글 문서 개방형 표준, **KS X 6101**. 국가표준으로 공개돼 있습니다.
- **DOCX / PPTX** — **ECMA-376 / ISO/IEC 29500**. 표준화 기구가 발행한 명세입니다.
- **HWP 5.0 바이너리** — 한글과컴퓨터가 **파일 형식 문서를 공개**했습니다.

즉 남의 프로그램을 뜯어보고 베낀 게 아니라, 공개된 명세대로 구현한 것입니다.
클린룸이니 역공학이니 하는 법적 회색지대와 무관합니다. 표준 문서를 읽고 구현하는 일은
처음부터 허용된 행위입니다.

### 2. "모르는 것을 건드리지 않는다"가 1순위

문서 편집기에서 제일 무서운 건 기능이 모자란 게 아니라, **열었다 저장했더니 뭔가
사라지는 것**입니다. 표가 날아가고 각주가 지워지면 그 프로그램은 두 번 다시 못 씁니다.

그래서 구조를 이렇게 잡았습니다.

- XML을 **무손실로 보존**하는 레이어를 의미 해석보다 먼저 둡니다. 속성 순서,
  `<a/>` 대 `<a></a>` 구분, 주석까지 그대로 유지해 바이트 수준 왕복이 됩니다.
- 편집은 **원본 트리를 제자리에서 고칩니다.** 모델을 다시 XML로 조립하지 않습니다.
  조립하는 순간 모델링하지 못한 것이 전부 사라지기 때문입니다.
- 해석하지 않는 파트(이미지, 테마, 차트, 폰트)는 **원본 바이트를 그대로 복사**합니다.

### 3. 구형 `.hwp`는 일부러 읽기 전용입니다

HWP 5.0 바이너리를 다시 쓰려면 레코드 트리 전체를 정확히 재구성해야 하고, 한 군데만
어긋나도 한글이 파일을 거부합니다. "저장은 되는데 안 열리는 파일"을 만드는 것보다,
읽어서 `.hwpx`로 내보내는 쪽이 안전하고 사용자가 보는 결과도 같습니다.

## 구조

```
packages/
  core/    무손실 XML DOM · 단위 변환(HWPUNIT/twip/EMU/pt) · 포맷 중립 문서 모델 · ZIP
  opc/     OPC 패키지 레이어 — [Content_Types].xml, _rels 관계 그래프 (docx·pptx 공용)
  hwpx/    HWPX(OWPML) 읽기/쓰기 + 모델→HWPX 변환
  hwp5/    구형 .hwp 읽기 — CFB(OLE2) 컨테이너 + 레코드 스트림
  docx/    WordprocessingML 읽기/쓰기
  pptx/    PresentationML 읽기/쓰기
apps/
  editor/  웹 편집기 (React + Vite)
```

HWPX·DOCX·PPTX가 전부 "ZIP 안의 XML"이라 `core`와 `opc`를 세 포맷이 공유합니다.
덕분에 네 포맷 엔진을 전부 합쳐도 번들이 87KB(gzip)입니다.

변환은 **포맷 중립 모델**을 경유합니다. n×n 조합 대신 n×2 어댑터로 끝납니다.

```
.hwp ─┐                    ┌─→ .hwpx
.hwpx ─┼─→ 중립 문서 모델 ─┼─→ .docx
.docx ─┘                    └─→ .pptx
```

자세한 내용은 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), 포맷 분석 노트는
[docs/formats/](docs/formats/)에 있습니다.

| 문서 | 내용 |
|---|---|
| [FEATURES.md](docs/FEATURES.md) | 워드·한글·PPT 대비 **무엇이 되고 무엇이 안 되는지** |
| [SHORTCUTS.md](docs/SHORTCUTS.md) | 단축키 전체와 브라우저 제약 |
| [ARCHITECTURE.md](docs/ARCHITECTURE.md) | 설계 결정과 포맷별 함정 |

## 검증

```bash
npm test           # 단위 테스트 101개
npm run typecheck  # 전체 타입 검사
npm run samples    # 각 형식 샘플 파일 생성
npm run test:e2e        # 브라우저 종단 테스트 (빌드 + 서버 필요)
npm run test:e2e:edit   # 단축키·서식·표·되돌리기 확인
npm run test:e2e:file   # 단일 HTML 파일이 file:// 에서 도는지 확인
```

단위 테스트만으로는 "내가 쓴 걸 내가 읽는다"까지밖에 보장되지 않습니다. 그래서
**다른 프로그램이 읽을 수 있는지**를 따로 확인했습니다.

- 생성한 `.docx`는 LibreOffice가 **Writer 문서로** 열고 PDF까지 렌더합니다.
  한글 텍스트·탭·앞뒤 공백이 모두 보존됩니다.
- 생성한 `.pptx`는 LibreOffice가 **Impress 문서로** 열고, 슬라이드 3장과 문단 9줄이
  순서대로 보존됩니다.
- 슬라이드 **렌더링**은 LibreOffice가 같은 파일을 그린 결과와 나란히 비교해
  확인했습니다. 배경 사진·장식 도형·테마 색이 거의 그대로 나옵니다.
- CFB(OLE2) 리더는 LibreOffice가 만든 실제 Word 97 / PowerPoint 97 파일로
  교차 검증했습니다 (442KB 스트림 포함, 모든 스트림 크기 정확히 일치).
- 표가 든 `.docx` 를 LibreOffice 가 3×3 표로 정확히 읽습니다 (셀 9개 내용 일치).
- 브라우저 종단 테스트: 파일 열기 → 편집 → 저장 → 재열기까지 실제 Chromium에서 확인.
  단축키(워드 키·한글 키 양쪽), 표 만들기와 줄·칸 추가, 되돌리기까지 포함합니다.
- 단일 HTML 파일이 `file://` 에서 실제로 뜨고 문서가 열리는지도 매번 확인합니다.
  인라인 스크립트는 번들 내용에 따라 조용히 깨집니다 — 실제로 한 번 깨졌습니다.
  XML 파서가 문자열로 들고 있던 `"<!--"` 를 HTML 파서가 주석 시작으로 읽어
  스크립트 뒷부분을 통째로 먹었습니다. 지금은 base64로 감싸 내용과 무관하게 합니다.

### 한글이 만든 진짜 파일로 확인했습니다

한컴오피스 한글이 뱉은 `.hwpx` 세 개로 검증했습니다 — 한글 13(2023)이 만든 빈
문서 하나, 한글 11이 만든 정부 기안문 서식 두 개(표 4개, 병합 셀 포함).

- 셋 다 열리고 글꼴·서식·스타일 표를 전부 읽습니다.
- **손대지 않고 저장하면 모든 XML 파트가 바이트까지 똑같습니다.** 미리보기
  이미지처럼 해석하지 않는 파트도 바이트 그대로입니다.
- 한글이 만든 표를 격자로 정확히 읽습니다.
- 고쳐서 저장해도 나머지가 그대로 남고, 워드로 변환하면 표까지 넘어갑니다.

손에 있는 `.hwpx` 로 같은 검사를 돌릴 수 있습니다:

```bash
npm run verify:real -- 어떤문서.hwpx
```

### 아직 확인하지 못한 것

**우리가 새로 만든 `.hwpx` 를 한글이 여는지는 아직 확인하지 못했습니다.**
읽기와 왕복은 진짜 파일로 증명했지만, 빈 문서를 처음부터 만들어 내는 경로는
한글이 설치된 환경에서의 확인이 남아 있습니다.

HWP 5.0 바이너리 리더도 **한글이 만든 실제 `.hwp` 로는 검증하지 못했습니다.**
합성 픽스처로만 확인했습니다.
