# 구조

## 설계를 가른 결정 네 가지

### 1. 의미 해석보다 보존을 먼저 둔다

HWPX와 OOXML은 스펙이 방대해서 전부 타입으로 모델링하는 건 비현실적입니다.
그런데 모델링하지 못한 요소를 버리면 **남의 문서를 조용히 파괴**합니다.

그래서 `@jamo/core`의 XML 레이어는 의미를 전혀 모릅니다. 대신 완전히 보존합니다.

- 속성을 배열로 보관해 **순서를 유지**합니다
- `<a/>`로 쓰였는지 `<a></a>`로 쓰였는지 기억합니다
- 주석·CDATA·처리 명령어를 그대로 남깁니다

그 결과 파싱 후 다시 직렬화하면 **바이트가 같습니다**. 테스트로 보장합니다.

타입드 접근은 그 위에 "뷰"로 얹습니다. 뷰가 모르는 건 트리에 그대로 남아 있습니다.

### 2. 편집은 원본 트리를 제자리에서 고친다

흔한 설계는 "파일 → 모델 → 편집 → 모델 → 파일"입니다. 하지만 마지막 단계에서
모델을 다시 XML로 조립하는 순간, 모델에 없는 것은 전부 사라집니다.

그래서 진실의 원천은 **엔진 객체(원본 XML 트리)** 로 두고, 모델은 화면에 그리기 위해
뽑아낸 **읽기용 요약**으로만 씁니다. 모델의 각 문단은 자기가 유래한 XML 요소를
`source`로 들고 있어서, 편집은 그 요소를 직접 고칩니다.

```
XmlElement (진실)  ←── 편집 ──  UI
      │
      └── toModel() ──→ JamoParagraph { source: XmlElement } ──→ 화면
```

### 3. 변환은 중립 모델을 경유한다

4개 포맷을 직접 이으면 12가지 변환기가 필요합니다. 중립 모델을 두면 8개로 끝나고,
포맷이 하나 늘 때 2개만 추가하면 됩니다.

중립 모델의 길이 단위는 **HWPUNIT(1/7200인치)으로 통일**했습니다. 단위가 섞이면
변환 버그가 끝없이 나옵니다. 각 어댑터가 경계에서 한 번만 환산합니다.

| 단위 | 1인치당 | 쓰는 곳 |
|---|---|---|
| HWPUNIT | 7200 | HWP/HWPX, 중립 모델 |
| twip | 1440 | DOCX 문단·페이지 |
| EMU | 914400 | PPTX 도형 좌표 |
| 1/100 pt | 7200 | HWPX `charPr/@height`, PPTX `sz` |
| half-point | 144 | DOCX `w:sz` |

### 4. 쓰기를 포기한 곳이 하나 있다

구형 `.hwp`(HWP 5.0 바이너리)는 읽기만 합니다. 레코드 트리를 재구성하다 한 군데만
어긋나면 한글이 파일을 거부합니다. "저장은 되는데 열리지 않는 파일"은 아무 기능도
없는 것보다 나쁩니다. 읽어서 `.hwpx`로 내보내면 사용자가 보는 결과는 같습니다.

## 패키지

### `@jamo/core`

- `xml/` — 의존성 없는 파서/직렬화기. 약 400줄.
- `units.ts` — 단위 변환표.
- `model.ts` — 포맷 중립 문서 모델.
- `zip.ts` — ZIP 입출력. OCF 규칙(mimetype 선두·무압축) 지원.

### `@jamo/opc`

DOCX와 PPTX가 공유하는 Open Packaging Conventions 레이어.

- `[Content_Types].xml` — 확장자 기본값(Default)과 파트별 재정의(Override)
- `_rels` 관계 그래프 — 관계의 `Target`은 **출처 파트 디렉터리 기준 상대 경로**입니다.
  `ppt/slides/slide1.xml`에서 `../slideLayouts/slideLayout1.xml`을 가리키는 식이라,
  이 계산을 틀리면 파트를 못 찾습니다. 가장 흔한 버그 지점이라 `paths.ts`로 분리했습니다.

### `@jamo/hwpx`

- `blank.ts` — 빈 문서 생성. 참조 구현의 번호 체계를 그대로 베끼지 않고,
  **서로 맞물리는 최소 집합**을 만듭니다. (참조 구현의 "바탕글" 스타일은 paraPr 3번을
  가리키는데, paraPr을 0번만 만들고 3번을 가리키면 깨진 문서가 됩니다.)
- `styles.ts` — header.xml의 참조 표를 풀어 실제 서식으로 바꿉니다.
- `convert.ts` — 모델 → HWPX. 서식을 모아 표를 만들고 본문이 번호를 가리키게 합니다.

### `@jamo/hwp5`

- `cfb.ts` — CFB(OLE2) 컨테이너. "파일 안의 작은 파일 시스템"입니다.
- `records.ts` — 레코드 스트림, FileHeader, 압축 해제.
- `document.ts` — DocInfo(글꼴·글자모양·문단모양)와 BodyText(문단) 해석.

### `@jamo/docx` / `@jamo/pptx`

각각 WordprocessingML / PresentationML 레이어. 읽기·편집·쓰기·빈 문서 생성.

### `apps/editor`

React + Vite. 상태는 `session.ts` 훅 하나에 모여 있고, 엔진 객체를 ref로 들고
`revision` 카운터를 올려 화면을 다시 뽑습니다.

## 포맷을 다루며 걸린 함정들

구현하면서 실제로 걸렸던 것들입니다. 문서에 잘 안 적혀 있거나, 적혀 있어도
놓치기 쉬운 것들입니다.

| 포맷 | 함정 |
|---|---|
| HWPX | `version.xml`의 속성명은 `targetApplication`이 아니라 **`tagetApplication`** 입니다. 스펙 자체의 오타이고, 고치면 한글이 못 읽습니다. |
| HWPX | `mimetype`은 ZIP의 **맨 앞에 무압축**으로 들어가야 합니다 (OCF 규칙). |
| HWPX | `paraPr`의 여백·줄간격이 `hp:switch` 안에 호환용으로 두 벌 들어 있을 수 있습니다. |
| HWPX | 섹션 첫 문단의 첫 런에 용지 설정(`hp:secPr`)이 있습니다. 그 문단을 지우면 용지 설정이 날아갑니다. |
| DOCX | `<w:b/>`는 굵게지만 `<w:b w:val="0"/>`은 **굵게 해제**입니다. 요소 존재만 보면 반대로 읽습니다. |
| DOCX | 앞뒤 공백이 있는 텍스트에는 `xml:space="preserve"`가 **반드시** 있어야 합니다. |
| DOCX | `w:sectPr`는 `w:body`의 **마지막 자식**이어야 합니다. 어기면 Word가 복구를 요구합니다. |
| PPTX | 슬라이드의 진짜 순서는 `p:sldIdLst`이고 **파일 이름은 순서를 보장하지 않습니다**. |
| PPTX | 테마의 `fillStyleLst`/`lnStyleLst`/`effectStyleLst`/`bgFillStyleLst`는 각각 **항목이 3개여야** 합니다. |
| PPTX | `p:sldIdLst`는 `p:sldSz`보다 앞에 와야 합니다 (스키마 순서). |
| HWP 5.0 | 레코드 길이 필드가 12비트라 `0xFFF`를 넘으면 **뒤따르는 4바이트**에 실제 길이가 옵니다. |
| HWP 5.0 | `PARA_TEXT`의 제어 문자는 폭이 다릅니다. 1 WCHAR짜리와 **8 WCHAR짜리**를 구분하지 않으면 뒤 문자열이 전부 밀립니다. |
| HWP 5.0 | 압축은 zlib 래퍼 없는 **raw deflate**입니다. |
| CFB | 4096바이트 미만 스트림은 일반 섹터가 아니라 **미니 스트림**에 64바이트 단위로 들어갑니다. |
