# 웹에 올리기

파일을 주고받는 대신 **주소 하나**로 쓰는 방법입니다. 올려 두면

- 새 판이 나오면 **앱이 스스로 알려 줍니다** ("새 판이 준비됐습니다 → 새로 고치기")
- 도구막대의 **앱 설치**로 바탕화면 아이콘이 생기고 전용 창으로 뜹니다
- 한 번 열어 두면 **인터넷 없이도** 열립니다
- 탐색기에서 `.pptx` `.hwpx` 를 더블클릭하면 이 앱이 엽니다

어느 쪽으로 올려도 **파일은 여전히 기기를 떠나지 않습니다.** 서버는 앱 자체를
내려주기만 하고, 문서 처리는 전부 브라우저 안에서 끝납니다.

---

## ① Vercel

저장소를 연결하면 `main` 에 올라갈 때마다 자동으로 다시 올라갑니다.

1. <https://vercel.com> 에 GitHub 계정으로 로그인
2. **Add New… → Project** → `mio-modu/word_powerpoint_adobe_etc` 선택 → **Import**
3. 설정은 **건드리지 말고 그대로 Deploy**
   저장소에 `vercel.json` 이 있어서 빌드 방법·출력 폴더·캐시 설정이 이미 적혀 있습니다.
4. 1~2분 뒤 `https://<프로젝트이름>.vercel.app` 이 나옵니다

`vercel.json` 이 하는 일 중 중요한 것:

| 설정 | 왜 |
|---|---|
| `sw.js` 는 캐시 금지 | 서비스 워커가 캐시되면 **새 판이 영원히 안 내려옵니다** |
| `assets/*` 는 1년 캐시 | 이름에 해시가 붙어 있어 내용이 바뀌면 이름도 바뀝니다 |
| `index.html` 은 `no-cache` | 매번 새 자산 이름을 확인해야 합니다 |

## ② GitHub Pages

새 계정이 필요 없습니다. 이미 `.github/workflows/pages.yml` 이 들어 있어서
**설정 한 번만** 바꾸면 됩니다.

1. 저장소 **Settings → Pages**
2. **Source** 를 **GitHub Actions** 로 변경
3. `main` 에 올라가면 자동으로 빌드·배포됩니다
4. 주소: `https://mio-modu.github.io/word_powerpoint_adobe_etc/`

워크플로는 올리기 전에 **타입 검사와 단위 테스트를 먼저 통과시킵니다.**
깨진 것이 올라가지 않습니다.

> 하위 경로(`/word_powerpoint_adobe_etc/`)에 올라가지만 문제없습니다.
> 빌드가 모든 경로를 상대 경로로 내보내기 때문입니다.

## ③ 파일 하나로 (서버 없이)

인터넷도 계정도 없이 쓰는 방법입니다.

```bash
npm run build:single
```

`apps/editor/dist/jamo-office-<판번호>.html` 이 나옵니다. 더블클릭하면 그대로
열리고 USB 에 넣어 다녀도 됩니다.

대신 이 방식에는 **자동 갱신이 없습니다.** 고친 내용을 받으려면 새 파일을
다시 만들어야 합니다. 그래서 파일 이름과 화면 왼쪽 위에 빌드 시각을 박아
두었습니다 — 받은 파일이 여러 개 쌓였을 때 어느 게 최신인지 보려면 그
숫자를 확인하세요.

## 새 판은 어떻게 전해지나

서버에 올려 둔 경우입니다.

1. 새 판을 올리면 `sw.js` 의 내용이 달라집니다 (미리 받아 둘 파일 목록의
   해시가 바뀝니다)
2. 브라우저가 그 차이를 보고 새 서비스 워커를 설치합니다
3. 설치가 끝나면 앱이 **"새 판이 준비됐습니다"** 막대를 띄웁니다
4. **새로 고치기** 를 누르면 새 판으로 바뀝니다

**스스로 새로고침하지는 않습니다.** 고치던 문서가 열려 있을 수 있고, 저장하지
않은 내용이 날아가면 알림보다 훨씬 나쁜 일이기 때문입니다. 막대에도 먼저
저장하라고 적어 둡니다.

앱은 15분마다 한 번씩 새 판이 있는지 조용히 확인합니다.
