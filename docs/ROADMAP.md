# 앞으로 할 일

지금은 "텍스트를 열고 고치고 저장한다"까지 됩니다. 표·이미지는 보존되지만 화면에
나오지 않습니다. 우선순위는 **실제로 문서를 쓰다 막히는 순서**로 잡았습니다.

## 끝난 것

- ~~표 렌더링과 편집~~ — HWPX·DOCX 모두 만들기/줄·칸 추가·삭제/셀 편집까지.
- ~~글자 서식 도구막대~~ — 굵게·기울임·밑줄·취소선·크기·색.
- ~~단축키~~ — 워드 키와 한글 키를 동시에 받습니다.
- ~~실행 취소/다시 실행~~ — 스냅샷 방식.
- ~~표 UI~~ — 격자 크기 선택기, 표 도구막대, Shift+클릭 범위 선택,
  셀 합치기·나누기, 칸 배경색, Tab 으로 칸 이동.
- ~~한글이 만든 실제 파일로 검증~~ — 읽기와 무손실 왕복을 증명했습니다.
- ~~슬라이드를 보이는 대로 그리기~~ — 테마 색, 배경, 그림, 도형 채우기와 모양,
  마스터·레이아웃 장식, 글자 서식 상속, 슬라이드 안 표.

## 다음 (쓰다 보면 바로 막히는 것)

1. **문서(한글·워드)의 이미지 표시** — 슬라이드는 끝났고 문서가 남았습니다.
   `BinData`/`word/media` 의 바이트를 Blob URL 로 만들어 띄우면 됩니다.
   삽입은 HWPX 의 `hp:pic`, DOCX 의 `w:drawing` 을 써야 합니다.
2. **찾기·바꾸기** — 블록 모델을 훑으면 되므로 어렵지 않습니다. 브라우저의
   `Ctrl+F` 를 가로채야 해서 UI 를 따로 붙여야 합니다.
3. **글머리표·번호 매기기** — 파일 안의 것은 이미 읽고 보존합니다. 새로 만들려면
   HWPX 는 `hh:numberings`, DOCX 는 `numbering.xml` 을 다뤄야 합니다.
4. **선택 영역 단위 서식** — 지금은 문단 단위로 적용합니다. 글자 몇 개만 굵게
   하려면 선택 경계에서 런을 쪼개야 하는데, 문서 구조를 흔드는 일이라 조심스럽게
   들어가야 합니다.
5. ~~표 셀 병합·나누기, 셀 배경색~~ — 끝났습니다.
6. **칸 너비 끌어서 조절** — 지금은 만들 때 균등 분할만 됩니다.
7. **슬라이드 도형 끌어 옮기기·크기 조절** — 좌표는 이미 정확히 읽습니다.
   화면에서 끌면 `a:off`/`a:ext` 를 고쳐 쓰면 됩니다.
8. **슬라이드 안 표 편집** — 읽기는 됩니다. HWPX·DOCX 와 달리 `a:tbl` 이라
   별도 경로가 필요합니다.

## 그다음 (품질)

6. **쪽 나눔 미리보기** — 지금은 용지 폭과 여백만 맞추고 쪽을 나누지 않습니다.
   제대로 하려면 글꼴 메트릭과 줄바꿈 규칙이 필요합니다. 어설프게 하면 실제 출력과
   달라져 오히려 혼란스러우므로, 할 거면 제대로 해야 합니다.
7. **머리말·꼬리말·쪽 번호**
8. **되돌리기를 스냅샷에서 명령 기록으로** — 지금은 편집할 때마다 문서 전체를
   직렬화해 쌓습니다. 작은 문서는 문제없지만 이미지가 많은 문서에서는 무겁습니다.
   명령과 그 역연산을 기록하는 방식으로 바꾸면 가벼워집니다.

## 검증 (가장 중요)

8. **한글에서 열리는지 확인** — 생성한 `.hwpx`를 한컴오피스 한글이 여는지 아직
   확인하지 못했습니다. 이게 확인되기 전까지 HWPX 쓰기는 "아마 될 것"입니다.
9. **실제 `.hwp` 파일로 리더 검증** — 합성 픽스처로만 확인했습니다. 관공서 공개
   문서 등 실제 파일 모음으로 회귀 테스트를 만드는 게 좋습니다.

## 나중에

10. **데스크톱 앱** — Tauri로 감싸면 파일 연결(더블클릭으로 열기)과 오프라인 설치가
    됩니다. 엔진이 순수 TypeScript라 그대로 돌아갑니다. **브라우저가 가져가던
    단축키(`Ctrl+N,T` 등)도 그때 원래대로 되돌릴 수 있습니다.** 연속 키 처리는
    이미 구현해 뒀으니 키 정의만 바꾸면 됩니다.
11. **`.xlsx`** — `@jamo/opc`를 그대로 씁니다. SpreadsheetML 레이어만 추가하면 됩니다.
12. **PDF 내보내기** — 쪽 나눔(4번)이 끝난 뒤에나 의미가 있습니다.
13. **구형 `.doc` / `.ppt`** — CFB 리더는 이미 있습니다. 그 위의 바이너리 포맷이
    HWP보다 훨씬 복잡해서 투자 대비 효과를 따져봐야 합니다.

## 하지 않기로 한 것

- **HWP 5.0 바이너리 쓰기.** 레코드 트리를 재구성하다 한 군데만 어긋나도 한글이
  파일을 거부합니다. "저장은 되는데 열리지 않는 파일"은 기능이 없는 것보다 나쁩니다.
- **서버 업로드.** 파일이 기기를 떠나지 않는다는 점이 이 도구의 핵심입니다.
  편의 기능을 위해 깨뜨리지 않습니다.
