# HWP 5.0 (구형 바이너리)

CFB(OLE2) 컨테이너 안에 압축된 레코드 스트림이 들어 있습니다.

## 컨테이너: CFB

"파일 안의 작은 파일 시스템"입니다. `.doc`, `.ppt`, `.xls`도 같은 컨테이너를 씁니다.

- 섹터 크기는 보통 512바이트. 섹터 N은 `(N+1) × 섹터크기` 위치에서 시작합니다.
- FAT이 섹터를 사슬로 잇습니다.
- 디렉터리 항목이 적흑트리로 묶여 있습니다 (항목 128바이트).

**함정 두 가지:**

1. **4096바이트 미만 스트림은 "미니 스트림"에 들어갑니다.** 일반 섹터가 아니라
   64바이트 단위 미니 섹터를 쓰고, 미니 FAT이 따로 있습니다. 이걸 놓치면 작은
   스트림이 전부 깨집니다. HWP의 `FileHeader`(256바이트)가 여기 해당합니다.
2. **FAT이 커지면 DIFAT 체인을 따라가야 합니다.** 헤더에 들어가는 건 앞쪽 109개뿐입니다.

## 스트림 구성

```
FileHeader              256바이트. 서명 + 버전 + 플래그
DocInfo                 글꼴·글자모양·문단모양·스타일
BodyText/Section0       본문
BodyText/Section1       …
BinData/BIN0001.png     첨부
PrvText                 미리보기 텍스트 (UTF-16LE)
```

`FileHeader`를 뺀 나머지는 플래그에 따라 압축돼 있습니다. **zlib 래퍼 없는
raw deflate**입니다.

### FileHeader

- 0–31: `"HWP Document File"` + 패딩
- 32–35: 버전 DWORD. `0x05000300` = 5.0.3.0
- 36–39: 플래그. bit0 압축, bit1 암호, bit2 배포용, bit4 DRM

## 레코드 스트림

4바이트 헤더가 붙은 레코드의 연속입니다.

```
비트  0–9   태그 ID
비트 10–19  트리 레벨
비트 20–31  데이터 길이
```

**길이 필드가 12비트라 `0xFFF`를 넘지 못합니다.** 길이가 `0xFFF`로 적혀 있으면
"12비트에 안 들어간다"는 표시이고, **실제 길이는 뒤따르는 4바이트**에 있습니다.
이 예외를 빠뜨리면 큰 표나 긴 문단이 있는 문서에서 파싱이 어긋납니다.

## PARA_TEXT의 제어 문자

UTF-16LE이지만 0–31은 제어 문자이고, **폭이 다릅니다.**

| 코드 | 폭 | 뜻 |
|---|---|---|
| 0, 10, 13, 24–31 | **1 WCHAR** | 줄바꿈, 하이픈, 빈칸 종류 등 |
| 그 외 1–23 | **8 WCHAR (16바이트)** | 표·그림·필드 같은 개체 참조 |

탭(9)이 8 WCHAR짜리라는 게 특히 함정입니다. 1개로 세면 그 뒤 문자열이 전부 밀립니다.

주요 1 WCHAR 제어 문자:

- `10` 줄바꿈
- `13` 문단 끝 (문단은 이미 레코드 단위로 나뉘므로 버려도 됩니다)
- `24` 하이픈
- `30` 묶음 빈칸 (non-breaking space)
- `31` 고정폭 빈칸

## 왜 쓰기를 지원하지 않는가

레코드 트리 전체를 정확히 재구성해야 하고, 한 군데만 어긋나도 한글이 파일을
거부합니다. 읽어서 `.hwpx`로 내보내는 쪽이 안전하고, 사용자가 보는 결과는 같습니다.
