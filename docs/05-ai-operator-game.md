# AI 활용 능력자 — 역량 평가 게임

> 발행: https://claude.ai/artifact/GkR3VNFBVhaQCnHCPoVW6g
> 소스: `game/index.html`

## 이 제품이 다른 AI 교육물과 다른 지점

대부분의 "AI 활용 교육"은 객관식이거나 영상 시청이다. 둘 다 **수료증이
실력을 증명하지 못한다.** 답을 외우면 통과하기 때문이다.

이 게임의 설계 전제는 하나다.

> **플레이어가 실제 프롬프트를 쓰고, 실제 모델이 그것을 보완 없이 실행한다.**

프롬프트가 모호하면 모호한 결과가 나온다. 플레이어는 자기 지시의 실제 성능을
눈으로 본다. 이것은 외울 수 없고, 대리 응시로 흉내 낼 수도 없다. 그래서
여기서 나온 점수만이 나중에 자격 체계로 발전할 수 있다.

## 평가 루브릭

실무 프롬프트 엔지니어링을 다섯 축으로 쪼갰다. 각 0~20점, 합계 100점.

| 축 | 묻는 것 |
|---|---|
| 역할·맥락 | AI에게 누구로서, 어떤 상황에서 일하는지 알려주었는가 |
| 구체적 지시 | 무엇을 할지가 해석의 여지 없이 분명한가 |
| 출력 형식 | 결과물의 형태·분량·구조를 지정했는가 |
| 제약·금지 | 하지 말아야 할 것과 지켜야 할 선을 걸었는가 |
| 기준·예시 | 좋은 결과의 판단 기준이나 예시를 주었는가 |

채점 프롬프트에 세 가지를 명시했다. 프롬프트에 **실제로 쓰여 있는 것만**
인정할 것, 길이로 점수를 주지 말 것, 축을 다루지 않았으면 0~4점을 줄 것.
후한 채점은 자격 체계의 신뢰를 무너뜨린다.

## 미션 설계

각 미션은 **하나의 축을 가르치도록** 배치했고, 실패하는 방식까지 설계했다.

| # | 의뢰 | 가르치는 것 | 이것을 빼먹으면 |
|---|---|---|---|
| 1 | 상품 소개글 | 역할·맥락 | 누구에게 파는 글인지 모르는 일반론이 나온다 |
| 2 | 불만 고객 응대 | 제약·금지 | 회사가 못 지킬 약속(전액 환불)을 AI가 해버린다 |
| 3 | 주문 데이터 정리 | 출력 형식 | 사람이 읽을 산문이 나와 300건 처리가 불가능하다 |
| 4 | 경쟁사 리뷰 분석 | 구조화된 사고 | 뻔한 요약이 나오고 의사결정에 못 쓴다 |
| 5 | 광고 카피 20종 | 수량·다양성 통제 | 비슷한 문장 20개 + 과장광고 위반이 나온다 |
| 6 | 계약서 핵심 추출 | 안전장치 | AI가 "문제없습니다"라고 단정해 사고가 난다 |
| 7 | 업무 자동화 설계 | 작업 분해 | 한 번의 거대 요청이 뭉개진다 |
| 8 | 신규 사업 런칭 | 종합 | 수료 판정 기준이 된다 |

2번과 6번이 핵심이다. 대부분의 교육이 "어떻게 시킬까"만 가르치고
**"무엇을 막을까"**를 안 가르친다. 실무 사고는 거기서 난다.

## 진행 구조

- **자산** — 보수 = 미션 보수 × (점수/100). 60점 미만은 절반만 지급.
- **AI 활용 지수(AIQ)** — 누적. 재도전 시 **이전 최고점과의 차이만** 가산한다.
  반복 입력으로 지수를 부풀릴 수 없다.
- **등급** — 인턴 → 주니어 → 시니어 → 리드 → 디렉터 → AI 활용 능력자
- **해금** — 직전 미션 60점 이상
- **수료** — 전 미션 70점 이상 + AIQ 560 이상. 등록번호가 발급된다.

## 자격증으로 가는 길 (설계된 수익 경로)

현재는 게임 내 기록이고, 페이지에도 "공인 자격이 아닙니다"를 명시했다.
허위 자격 표시는 법적 문제가 된다. 단계는 아래 순서여야 한다.

1. **무료 플레이로 표본을 모은다** — 점수 분포가 쌓여야 기준선이 생긴다
2. **재응시·상위 과제를 유료화한다** — 자격이 아니라 평가 서비스로 판다
3. **점수 분포가 안정되면 등급 기준을 공개한다** — 이때부터 신뢰가 생긴다
4. **기업 단체 평가로 확장한다** — 실제 지불 주체는 개인이 아니라 회사다
5. **민간자격 등록 요건을 검토한다** — 등록 전에는 "자격증"이라 부르지 않는다

## 런타임 구성

| 기능 | 용도 |
|---|---|
| `sample` | 플레이어 프롬프트의 실행 + 채점. 게임의 심장 |
| `user` | 플레이어 식별(`id()`). 순위표 행의 소유자 |
| `db` | `players` 컬렉션 — 순위표와 진행 기록 |

접근 규칙:

```
players          read: view    write: owner
players/{self}                 write: interact
```

**누구나 순위표를 읽지만, 자기 행만 쓸 수 있다.** 발행 후 실제로 검증했다.

- 소유자 쓰기 → 성공
- `view` 레벨 읽기 → 성공 (순위표가 보인다)
- `view` 레벨 쓰기 → 거부
- `interact` 레벨로 남의 행 덮어쓰기 → 거부 (not found 로 반환)

마지막 항목이 부정 방지의 핵심이다. 플레이어가 남의 점수를 조작할 수 없다.

로컬 진행은 `localStorage` 에도 둔다. 비로그인 상태에서도 게임은 돌아가되
채점과 순위표만 비활성화된다.
